## 1. System Overview & Baseline Context

This repository (`https://github.com/pantana-na/extracter-agent.git`) serves as the foundation for the **Extracter Agent**, an autonomous cognitive AI agent built on the official **Google Agent Development Kit (`google-adk`)** and targeted for deployment on the **Gemini Enterprise Agent Platform (`agent_runtime`)**.

The platform is designed to ingest complex chemical engineering documentation (process data sheets, P&IDs, PFDs, operating manuals, and standards) stored in `reference/raw`, extract structured domain knowledge mirroring expert-verified extractions in `reference/wiki`, and compile them into **Open Knowledge Format (OKF v0.2)** bundles deposited into **Google Cloud Storage (GCS)**.

---

## 2. Baseline Architecture & Runtime Decoupling

The repository enforces strict separation of concerns across two runtime environments:

| Dimension | Autonomous AI Agents & Knowledge Engine | Web Frontend, API Gateway & Proxies |
| :--- | :--- | :--- |
| **Target Runtime** | **Gemini Enterprise Agent Platform (`agent_runtime`)** | **Google Cloud Run (`cloud_run`)** |
| **Deployed Artifacts** | ADK Root Coordinator (`ExtracterAgent`), extraction subagents, cognitive prompts, and structured `FunctionTool` registries. | React/Vite application, FastAPI/Express reverse proxy, streaming SSE endpoints, health probes (`/healthz`). |
| **Deployment Mechanism** | `agents-cli deploy --deployment-target agent_runtime` | Google Cloud Build (`cloudbuild.yaml`) + Terraform via Google Cloud Infrastructure Manager |
| **Core Responsibilities** | LLM reasoning (Gemini Flash), PDF extraction, OKF synthesis, GCS sync, trajectory evaluation (`agents-cli eval`). | HTTP/HTTPS ingress, IAP authentication, streaming proxying to the Agent Platform. |
| **Governance Rule** | `_agents/rules/google_adk_and_agent_runtime.md` | `_agents/rules/devops_security_and_quality_standards.md` |

## 3. Authoritative Reference Materials (Immutable)

The `reference/` directory contains authoritative domain knowledge and is **strictly read-only**:

### 3.1 Raw Engineering Documents (`reference/raw/`)
Contains 224 raw files (~52 MB) across 5 primary subdirectories:
- `data_sheets/`: Mechanical and process equipment data sheets (e.g. `14780-8120-PS-V2301...`).
- `operating_manuals/`: Operational manuals and procedural specifications.
- `pfd/`: Process Flow Diagrams illustrating mass/energy balances and stream properties.
- `pid/`: Piping and Instrumentation Diagrams detailing instrumentation, valves, interlocks, and pipe lines.
- `standards/`: Engineering design specifications and licensor standards (e.g. UOP).

### 3.2 Expert-Verified Reference Extractions (`reference/wiki/`)
Contains 54 verified Markdown files (~2.5 MB) across 9 domain categories:
- `equipment/`: Equipment tags, design data, packed bed details, and nozzles.
- `hazards/`: Thermal runaway risks, chemical toxicity, and operating safety boundaries.
- `hazop/`: HAZOP study nodes, deviations, causes, consequences, and safeguards.
- `instruments/`: Transmitters, controllers, control valves, alarm limits, and interlocks.
- `parameters/`: Process variables, operating limits, and trip settings.
- `procedures/`: Standard operating procedures, startup, shutdown, and emergency actions.
- `units/`: Process section boundaries (Alkylation, Oxidation, CDN, Distillation, ETP).
- `sources/`: Document provenance and cross-references.
- `troubleshooting/`: Failure modes and corrective actions.

## 4. Open Knowledge Format (OKF v0.2) Baseline Contract

Knowledge artifacts generated by the agent must strictly comply with **OKF v0.2**:

1. **Document Structure:**
   - UTF-8 Markdown file with opening and closing `---` delimited YAML frontmatter block.
   - Conventional Markdown body sections (`# Overview`, `# Design Data`, `# Operating Conditions`, `# Hazards & Safeguards`, `# Connections & Streams`).
2. **Frontmatter Fields:**
   - `type` (REQUIRED): Descriptive concept type (e.g., `Equipment Concept`, `Hazard Profile`, `HAZOP Study`, `Instrument Specification`).
   - `title`: Display name of the concept.
   - `description`: Single-sentence summary for progressive disclosure and search indexing.
   - `resource`: Canonical URI (e.g., `gs://<bucket>/<prefix>/<path>`).
   - `tags`: Cross-cutting categorization list.
   - `sources`: List of input sources with provenance, credibility signals (`author`, `usage_count`, `last_modified`), and join keys (`id`).
   - `generated`: Actor convention `{ by: extracter_agent/gemini-3.8-flash, at: ISO-8601 }`.
   - `verified`: Verification history `{ by: human:<id> | process:<id>, at: ISO-8601 }`.
   - `status`: Lifecycle status (`draft` | `stable` | `deprecated`).
3. **Progressive Disclosure & Navigation:**
   - Every directory contains an auto-generated `index.md` grouping entries by `type`.
   - The bundle root contains a chronological update log (`log.md`).

## 5. System Invariants & Quality Rules

1. **Reference Immutability Invariant:** Under no circumstances may any agent or tool modify, delete, or write into `reference/`.
2. **Zero Regex / Keyword Routing Invariant:** Intent classification, tool routing, and entity resolution must use cognitive model-driven reasoning via Gemini structured schemas; regex or keyword heuristics are prohibited.
3. **Frontmatter Completeness Invariant:** Every generated OKF document must have a non-empty `type` string and valid YAML frontmatter.
4. **Attribution Join Invariant:** Any Markdown footnote citation `[^source_id]` in the body must correspond to a valid `id` within `sources[]`.
5. **Timestamp Invariant:** All datetime fields must be ISO 8601 strings with explicit UTC offsets (`YYYY-MM-DDTHH:MM:SSZ`).

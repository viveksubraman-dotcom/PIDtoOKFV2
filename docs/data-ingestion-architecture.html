Dual-Mode Data Ingestion & Autonomous OKF v0.2 Extraction Architecture

Mode A (Entity-Centric / Equipment ID) & Mode B (Raw PDF File-by-File Incremental) • Google ADK • Gemini 3.8 Flash (Global) • Revision-Aware Read-Merge-Upsert

1. Dual Ingestion Modes (Mode A & Mode B)

  • • Mode A — Entity-Centric (Equipment / Concept ID): Query by tag (e.g., D-2304, V-2301, sis-cdn). The agent autonomously discovers all relevant Datasheets, P&IDs, PFDs, and Manuals to synthesize the complete OKF v0.2 concept in one pass (--dataset wiki, 130 cases).
  • • Mode B — Raw PDF File-by-File Incremental: Feed raw PDFs one by one (e.g., data_sheets/*.pdf then pid/*.pdf). The agent creates sources/<doc>.md and incrementally enriches every concept in that file via non-destructive Read-Merge-Upsert (--dataset file-by-file, 136 PDFs).

2. Hybrid Extraction & Revision-Aware Merge

  • • Hybrid PDF + 300 DPI Vision: Extracts digital text/tables via PyMuPDF and renders vector CAD P&IDs/PFDs at 300 DPI for gemini-3.8-flash visual inspection (cached by SHA-256).
  • • Revision Supersession vs. Conflict Callouts: Newer revisions of the same document (Rev Z0 → Rev Z1) update values in-place with zero false conflicts; cross-document (Datasheet vs. P&ID) or multi-sheet (Sheet 1 vs. Sheet 4) discrepancies emit ⚠️ CONFLICT — <PARAMETER>.
  • • Structured & Table Merge: Both merge_equipment_entity_with_existing and merge_markdown_bodies preserve prior sections, table rows (by Tag/Parameter), and safety callouts across PDFs.

3. Two-Tier GCS Storage & Content-Hash Cache

  • • Cloud-Native GCS Store (USE_GCS_STORAGE=true): Reads 136 raw PDFs from gs://.../reference/raw/ and writes OKF v0.2 concepts to gs://.../okf-bundles/phenol-plant/ + local build/okf_bundle/.
  • • MD5 & mtime_ns Cache Hardening: Verifies base64 MD5 digests (blob.md5_hash) on raw PDF downloads and batch GCS uploads so in-place updated files (even equal byte size) are immediately re-ingested and synced.
